# UniApp Vue3 微信小程序项目编码规范与开发指南

## 项目概述

本项目是基于 Vue 3 + TypeScript + Vite + UniApp + Pinia 的微信小程序开发模板，提供完整的工具函数和最佳实践。

### 技术栈
- **框架**: Vue 3.4+ (Composition API)
- **构建工具**: Vite 5.4+
- **跨端框架**: UniApp 3.0+
- **语言**: TypeScript 4.9+
- **状态管理**: Pinia 2.0+
- **样式**: SCSS
- **包管理**: pnpm / npm

---

## 文件命名与组织规范

### 文件命名
- **页面文件**: 使用小写，一个页面一个文件夹，如 `pages/index/index.vue`
- **组件文件**: 使用 PascalCase，如 `UserAvatar.vue`、`ProductCard.vue`
- **工具函数文件**: 使用 camelCase，如 `utilsTool.ts`、`uniRouter.ts`
- **样式文件**: 与组件/页面同名，使用 `<style>` 标签内联，或使用 `index.scss`
- **类型定义文件**: 使用 `index.ts` 统一导出，或使用 `.d.ts` 声明文件

### 目录结构

## 代码风格规范

### 基本规则
- **引号**: 使用单引号 `'`，不使用双引号
- **分号**: 不使用分号（Prettier 配置 `semi: false`）
- **缩进**: 使用 2 个空格，不使用 Tab
- **行宽**: 最大 130 个字符
- **尾随逗号**: 不使用尾随逗号
- **箭头函数**: 参数必须使用括号包裹（`arrowParens: 'always'`）

### 变量命名
- **组件名**: PascalCase，如 `UserProfile`、`ProductList`
- **变量/函数名**: camelCase，如 `userInfo`、`getUserData`
- **常量**: 全大写下划线，如 `BASE_API`、`TOKEN_KEY`
- **类型/接口**: PascalCase，如 `UserInfo`、`ApiResponse`
- **私有属性**: 使用下划线前缀（如需要），如 `_internalData`

### 代码格式示例
```typescript
// ✅ 正确
const getUserInfo = async (id: number) => {
  const { data } = await getUserApi(id)
  return data
}

// ❌ 错误
const getUserInfo = async id => {
  const { data } = await getUserApi(id);
  return data;
}
```

## Vue 组件编写规范

### 组件结构
1. **单文件组件**: 统一使用 `.vue` 单文件组件
2. **Composition API**: 统一使用 Composition API 和 `<script setup>` 语法
3. **默认导出**: 页面和组件不需要显式导出（`<script setup>` 自动导出）
4. **Props 类型**: 使用 `defineProps` 定义 Props 类型

### 生命周期使用规范
- **页面生命周期**: 使用 UniApp 提供的生命周期钩子
  - `onLoad`: 页面加载时触发
  - `onShow`: 页面显示时触发
  - `onReady`: 页面初次渲染完成
  - `onHide`: 页面隐藏时触发
  - `onUnload`: 页面卸载时触发
- **组件生命周期**: 使用 Vue 3 的 Composition API 生命周期
  - `onMounted`: 组件挂载后
  - `onUnmounted`: 组件卸载前
  - `onUpdated`: 组件更新后

### 组件示例
```typescript
// ✅ 正确 - 页面组件
<script setup lang="ts">
import { ref, reactive } from 'vue'
import { onLoad, onShow } from '@dcloudio/uni-app'
import { useUserStore } from '@/stores/user'
import { getUserInfoApi } from '@/api/user'
import type { IUserInfo } from '@/types/user'

const userStore = useUserStore()
const loading = ref<boolean>(false)
const userInfo = reactive<IUserInfo>({
  id: 0,
  name: '',
})

onLoad(async (options) => {
  console.log('页面参数:', options)
  await loadUserInfo()
})

onShow(() => {
  console.log('页面显示')
})

const loadUserInfo = async () => {
  try {
    loading.value = true
    const { data } = await getUserInfoApi()
    Object.assign(userInfo, data)
  } finally {
    loading.value = false
  }
}
</script>

<template>
  <view class="container">
    <view v-if="loading">加载中...</view>
    <view v-else>{{ userInfo.name }}</view>
  </view>
</template>

<style lang="scss" scoped>
.container {
  padding: 20rpx;
}
</style>
```

### 组件最佳实践
- **响应式数据**: 使用 `ref` 处理基本类型，使用 `reactive` 处理对象
- **计算属性**: 使用 `computed` 处理派生状态
- **条件渲染**: 使用 `v-if`、`v-else-if`、`v-else` 或 `v-show`
- **列表渲染**: 使用 `v-for`，必须提供 `key` 属性
- **事件处理**: 使用 `@click`、`@input` 等事件绑定

## Pinia 状态管理规范

### Pinia Store 使用
- **Store 定义**: 使用 `defineStore` 创建 store
- **Store 命名**: 使用 camelCase + `Store` 后缀，如 `useUserStore`
- **状态类型**: 使用 TypeScript 接口定义 state 类型
- **Store 导出**: 使用命名导出

### Pinia Store 示例
```typescript
// ✅ 正确 - Pinia Store
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import { getUserInfoApi } from '@/api/user'
import type { IUserInfo } from '@/types/user'

interface UserState {
  userInfo: IUserInfo | null
  token: string
}

export const useUserStore = defineStore('user', () => {
  // State
  const userInfo = ref<IUserInfo | null>(null)
  const token = ref<string>('')

  // Getters
  const isLoggedIn = computed(() => !!token.value)
  const userName = computed(() => userInfo.value?.name || '')

  // Actions
  const setUserInfo = (info: IUserInfo) => {
    userInfo.value = info
  }

  const setToken = (newToken: string) => {
    token.value = newToken
    uni.setStorageSync('token', newToken)
  }

  const login = async (loginForm: { username: string; password: string }) => {
    const { data } = await loginApi(loginForm)
    setToken(data.token)
    await loadUserInfo()
  }

  const loadUserInfo = async () => {
    const { data } = await getUserInfoApi()
    setUserInfo(data)
  }

  const logout = () => {
    userInfo.value = null
    token.value = ''
    uni.removeStorageSync('token')
  }

  return {
    userInfo,
    token,
    isLoggedIn,
    userName,
    setUserInfo,
    setToken,
    login,
    logout,
  }
})
```

### Pinia 使用规范
- **状态选择**: 在组件中使用 store，直接解构或使用 store 实例
- **响应式解构**: 使用 `storeToRefs` 解构响应式状态（如需要）
- **Actions 调用**: 直接调用 store 的 actions 方法

## API 接口管理规范

### API 文件组织
- **按模块划分**: 每个业务模块一个文件，如 `user.ts`、`order.ts`
- **接口前缀**: 使用统一的 `prefix` 常量，如 `/api/v1/weapp`
- **接口命名**: 使用 camelCase + `Api` 后缀，如 `getUserInfoApi`、`loginApi`

### API 调用示例
```typescript
// ✅ 正确 - API 定义
import request from '@/utils/request'

export const prefix = '/api/v1/weapp'

export const getUserInfoApi = () => {
  return request<IUserInfo>({
    url: `${prefix}/user/info`,
    method: 'GET',
  })
}

export const loginApi = (params: { username: string; password: string }) => {
  return request<{ token: string }>({
    url: `${prefix}/auth/login`,
    method: 'POST',
    params,
  })
}

// ✅ 正确 - API 调用
const { data } = await getUserInfoApi()
const { data: loginData } = await loginApi({ username, password })
```

### 错误处理
- **统一处理**: 在 `utils/request.ts` 的拦截器中统一处理错误
- **成功提示**: 在组件中根据业务需求处理成功提示
- **错误提示**: 错误信息由请求拦截器统一处理，组件中无需重复处理

## 路由导航规范

### 路由导航 API
- **打开新页面**: 使用 `navigateTo` 函数（对应 `uni.navigateTo`）
- **关闭当前页面并跳转**: 使用 `redirectTo` 函数（对应 `uni.redirectTo`）
- **返回上一页**: 使用 `navBack` 函数（对应 `uni.navigateBack`）
- **跳转 TabBar**: 使用 `switchTab` 函数（对应 `uni.switchTab`）
- **重新加载**: 使用 `reLaunch` 函数（对应 `uni.reLaunch`）

### 路由导航示例
```typescript
// ✅ 正确 - 路由导航
import { navigateTo, redirectTo, navBack } from '@/utils/uniRouter'

// 打开新页面
navigateTo('/pages/user/profile', { id: 123 })

// 关闭当前页面并跳转
redirectTo('/pages/login', { from: 'home' })

// 返回上一页
navBack()

// 带参数跳转
navigateTo('/pages/detail', {
  id: 123,
  type: 'product',
})
```

### pages.json 配置规范
- **页面路径**: 所有页面路径必须在 `pages.json` 中配置
- **TabBar 配置**: TabBar 页面需要单独配置
- **分包配置**: 使用 `subPackages` 配置分包页面

## 样式编写规范

### SCSS 使用规范
- **样式作用域**: 使用 `scoped` 作用域，避免样式污染
- **单位使用**: 使用 `rpx` 作为尺寸单位（响应式像素），1rpx = 屏幕宽度/750
- **类名命名**: 使用 kebab-case，如 `user-profile`、`product-card`
- **全局样式**: 在 `uni.scss` 中定义全局样式变量

### 样式示例
```scss
// ✅ 正确 - SCSS 样式
<style lang="scss" scoped>
.user-profile {
  padding: 20rpx;

  .avatar {
    width: 120rpx;
    height: 120rpx;
    border-radius: 50%;
  }
  
  .name {
    font-size: 32rpx;
    color: #333;
    margin-top: 20rpx;
  }
```

### 样式最佳实践
- **响应式设计**: 使用 `rpx` 单位实现响应式布局
- **避免内联样式**: 尽量使用 className，避免内联 style
- **复用样式**: 提取公共样式到全局样式文件或 mixin
- **小程序限制**: 注意小程序不支持的 CSS 特性（如 `position: fixed` 在某些场景下）

## 工具函数规范

### 工具函数组织
- **文件命名**: 使用 camelCase，如 `utilsTool.ts`、`uniRouter.ts`
- **函数导出**: 使用命名导出 `export const functionName`
- **函数注释**: 使用 JSDoc 格式注释，包含 `@description`、`@param`、`@return`

### 工具函数示例
```typescript
/**
 * @description 获取localStorage
 * @param {String} key Storage名称
 * @return any
 */
export const getStorage = (key: string) => {
  try {
    const value = uni.getStorageSync(key)
    return value ? JSON.parse(value) : null
  } catch (error) {
    return uni.getStorageSync(key)
  }
}

/**
 * @description 设置localStorage
 * @param {String} key Storage名称
 * @param {any} value 存储值
 */
export const setStorage = (key: string, value: any) => {
  uni.setStorageSync(key, JSON.stringify(value))
}
```

### 工具函数分类
- **存储工具**: `getStorage`、`setStorage`、`removeStorage`、`clearStorage`
- **路由工具**: `navigateTo`、`redirectTo`、`navBack`、`switchTab`、`reLaunch`
- **数据处理**: `convertParams`、`formatDateTime`、`maskPhone`
- **设备信息**: `getComputerSystem`、`getSystemInfo`
- **文件处理**: `uploadFilePromise`、`imageToBase64`

## 小程序特有规范

### 页面配置
- **pages.json**: 必须配置所有页面路径
- **页面路径**: 页面路径必须以 `/` 开头，如 `/pages/index/index`
- **TabBar 配置**: TabBar 页面路径必须正确配置

### 生命周期
- **页面生命周期**: 使用 UniApp 提供的页面生命周期钩子
- **应用生命周期**: 在 `App.vue` 中使用 `onLaunch`、`onShow`、`onHide`

### 限制与注意事项
- **不支持 DOM API**: 小程序不支持 `document`、`window` 等 DOM API
- **样式限制**: 不支持某些 CSS 特性（如 `position: fixed` 在某些场景下）
- **代码包大小**: 注意代码包大小限制（主包 2MB，单个分包 2MB）
- **网络请求**: 必须配置合法域名（生产环境）
- **图片资源**: 建议使用网络图片或 base64，本地图片会占用代码包大小

### 性能优化
- **图片优化**: 使用合适的图片格式和尺寸
- **代码分包**: 使用分包加载减少主包大小
- **懒加载**: 长列表使用虚拟滚动或分页加载
- **数据缓存**: 合理使用本地存储缓存数据

## 最佳实践与注意事项

### 组件开发
1. **单一职责**: 每个组件只负责一个功能
2. **组件复用**: 提取公共逻辑到工具函数或 composables
3. **性能优化**: 合理使用 `computed`、`watch` 优化性能
4. **错误处理**: 使用 `try-catch` 处理异步操作错误

### 状态管理
1. **状态提升**: 将共享状态提升到 Pinia store
2. **避免过度使用**: 局部状态使用组件内部状态，全局状态使用 Pinia
3. **状态持久化**: 使用 `uni.setStorageSync` 持久化重要状态

### 类型安全
1. **类型定义**: 为所有函数参数和返回值定义类型
2. **接口优先**: 优先使用 `interface` 而非 `type`
3. **类型导入**: 纯类型使用 `import type` 导入

### 代码注释
1. **函数注释**: 所有公共函数使用 JSDoc 格式注释
2. **复杂逻辑**: 对复杂业务逻辑添加注释说明
3. **TODO 标记**: 使用 `// TODO:` 标记待完成功能

### 错误处理
1. **异步错误**: 使用 `try-catch` 处理异步操作错误
2. **用户提示**: 使用 `uni.showToast` 或 `uni.showModal` 提示用户
3. **错误日志**: 重要错误记录到控制台

### 安全规范
1. **敏感信息**: 不在代码中硬编码敏感信息（API Key、Token 等）
2. **输入验证**: 验证用户输入，防止 XSS 攻击
3. **权限控制**: 合理使用权限控制功能访问
